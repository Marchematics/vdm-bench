# VDM-Bench reference leaderboard (v0.1)

Generated by `run_reference.py` on a 256-vCPU CPU host (8 BLAS threads). The fast reference
set is deterministic; `--full` adds the optional AnaVec/VecProf reference submissions
(costlier). Regenerate with:

```bash
python prepare.py --data-root /path/to/data --out workloads
python run_reference.py --data-root /path/to/data --workloads workloads
```

## Serving (8 tenants, 2k queries/tenant; measured IVF-256 surface)

| submission | SLO pass | p95 latency (ms) | recall-SLO | goodput (q/s) |
|---|---|---|---|---|
| serving-static | 1.000 | 2.049 | 1.000 | 305.5 |
| serving-adaptive | 0.692 | 0.961 | 0.692 | 211.5 |
| serving-oracle | 1.000 | 2.049 | 1.000 | 305.5 |

`serving-adaptive` ignores query difficulty; `serving-static` overpays with 2x effort for every
query; the oracle knows the hidden difficulty. A submission that predicts hardness from a cheap
signal should land between adaptive and oracle — that is the task.
