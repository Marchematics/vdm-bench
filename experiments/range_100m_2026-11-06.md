# 100M real SIFT: the allocation lever holds, the prefix lever stays dead

First measurement at **100,000,000 real SIFT vectors** (1,000 shards of `VDB_Benchmark/sift1b`
from ModelScope, rescaled x255 like the 1M/10M pipelines, ingested to a 51 GB float32 memory map).

| item | value |
|---|---|
| collection | 100,000,000 x 128 float32 (SIFT1B shards, direct download 9.1 MB/s) |
| index | IVF, `nlist = 2,000` (list population ~50,000) |
| queries / radii | 20 SIFT queries x 5 pooled-distance quantiles (0.5/2/5/20/50%) |
| exact counts | 509,185 / 2,011,226 / 5,018,067 / 20,031,297 / 50,017,422 (0.51% - 50.0% of N) |
| budget | 1,000,000 distance evaluations per query (= 1% of N), identical for every rung |
| host | `joysuch`, CPU only, `nice 15`, 224 threads |

## Attribution ladder (one rung per design decision)

| rung | mean rel. err | p95 | cost / query | gain vs previous |
|---|---|---|---|---|
| 1 uniform sampling | 0.005931 | 0.02000 | 1.0e6 | — |
| 2 proportional strata (`s_c ∝ size_c`) | 0.005957 | 0.02712 | 1.0e6 | **none** (cells are too coarse at this `nlist`) |
| 3 Neyman, spherical `p_c` | 0.004173 | 0.01421 | 1.0e6 | 1.43x |
| 4 **Neyman, angle-aware `p_c`** | **0.003499** | **0.01287** | 1.0e6 | 1.19x (total **1.69x** over uniform) |
| 5 exact prefix 16 lists + allocation | 0.006325 | 0.02497 | 2.0e7 | **worse**, at 20x the cost |
| 5 exact prefix 64 lists + allocation | 0.084476 | 0.27454 | 5.5e7 | much worse, at 55x the cost |

## What this establishes

1. **Allocation is scale-invariant in its advantage.** 1.69x here against 1.66-1.81x at 10M, both
   at matched cost: the lever does not decay as the collection grows 10x.
2. **The lever inversion is now measured at three scales, same protocol.** 100k: the exact prefix
   wins (9.05x vs same-cost sampling). 10M: prefix loses (0.217 vs 0.016 at 140x the cost).
   100M: prefix loses harder (0.0063 at 20x, 0.084 at 55x). Allocation is the lever that survives.
3. **Proportional stratification stops helping at 100M** (0.00596 vs 0.00593 uniform): with list
   population 50,000 the cells are too coarse for stratum homogeneity, so the win is entirely the
   Neyman allocation plus the angle-aware predictor. This is exactly the diagnostic the ladder is
   for - it locates the gain in a named mechanism instead of attributing it to "the index".
4. Absolute error is lower than at 10M (0.0035 vs 0.0147) because the budget is 1% of N in both
   cases, so the sample count grows with the collection; the *ratio* between rungs is what carries
   across scales.

## Caveats (stated, not hidden)

* 20 queries x 5 radii = 100 observations (the 10M study used 500); single seed.
* `nlist = 2,000` (population 50,000) was chosen so the run fit a wall-clock window, not because it
  is optimal; the 10M study used population ~1,000. Rung 2's null result is caused by this choice
  and is reported as such.
* No oracle-allocation row at 100M (it needs a second full pass over 51 GB; deferred).
* coverage / join are **not applicable** at 100M: building HNSW on 100M is not feasible here, and
  substituting a downsampled candidate index would be a different benchmark, so it is not done.
* A 3-seed version and the oracle rung are the next measurements; the caches
  (`X.f32.npy` 51 GB, `cells_100000000.npz`, `wl_*`) persist on the host so those cost minutes.
